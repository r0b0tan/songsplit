2. The music stays on your device

MixApart takes a song apart into separate stems. The computing happens in the browser. The file you drop into the field is read on your device, decoded there and separated there. It is not uploaded.

Nothing from that file reaches the MixApart server. Not the file, not its name, not its length. The separated stems are created in the memory of the browser tab and are gone as soon as the tab is closed or the page is reloaded. Anyone who wants to keep a stem saves it as a file on their own device.

There is one exception, and it only happens on explicit request. Some devices do not release their graphics unit to the browser, phones above all. The app cannot compute there, and nothing on the device can change that. For those cases MixApart offers to have the separation done on a server. As long as the device can compute for itself, that route is not even offered, and it never starts by itself. What happens on it is described in the next section.

3. The server route, when it is chosen

Not every device can compute the separation itself. On Android, browsers have so far released the graphics unit for only some of the models in use. For those devices MixApart offers to compute on a server. The decision is always made on the device. The route only appears as an option when the device cannot compute for itself, and it is only taken after an explicit click.

What is transferred

On this route the audio file goes to the server and is taken apart into stems there. What is transferred is the file itself, its file name and the IP address of the device. The finished stems come back to the device.

Whatever is inside the file travels with it. Many music files carry a title, artist, album and occasionally more in their header. MixApart reads none of it and evaluates none of it. It is transferred regardless, because the file is transferred as a whole. Anyone who would rather not have that removes these details beforehand, or stays with the route on the device.

Requests to this endpoint are logged by the compute provider, as on any server. Those logs contain the time, the IP address and the path that was called. What MixApart itself writes into that log is the name of the graphics card used and the number of stems. Nothing from the transferred file appears there.

Where the computing happens

The separation is carried out on behalf of CLICKIT DIGITAL by Modal Labs, Inc., 233 Spring Street, 11th Floor, New York, NY, USA. The company does not operate data centres of its own but uses data centre operators as sub-processors. The current list is available at trust.modal.com/subprocessors.

No particular location is fixed. The processing is not tied to a region, and some of the operators used work worldwide. It therefore takes place in the USA or in other third countries outside the European Union. The next part concerns that.

Legal basis

The legal basis for the processing is consent under Art. 6(1)(a) GDPR. It is given by selecting the server route and starting the separation. Without that selection no transfer takes place.

A data processing agreement under Art. 28 GDPR is in place with Modal Labs, Inc. It forms part of the terms of use (modal.com/legal/dpa). The transfer to third countries is based on the EU Standard Contractual Clauses under Implementing Decision (EU) 2021/914, Module 2 (controller to processor), which are incorporated in Annex 1 of that agreement (Art. 46(2)(c) GDPR). They also cover the onward transfer to the sub-processors named above.

The USA does not have a level of data protection equivalent to that of the European Union. That should be stated plainly here. Authorities in the USA and in other third countries may, under certain conditions, access data stored there without the same scope of legal remedies being available as within the EU. The Standard Contractual Clauses do oblige the provider to maintain an adequate level of protection, but they cannot remove that risk. A transfer therefore only takes place when it is chosen in the knowledge of this. The server route is never preselected.

How long data is stored

MixApart deletes the separated stems automatically, at the latest six hours after they are created. Independently of that, the compute provider stores the data passed to a function and its results for up to seven days by its own account, and deletes them afterwards. The music is not stored permanently. There is no user account, and files are not associated with one.

The music is not analysed, not passed on to third parties and not used to train models. The separation model used is the same one that would run on the device. It does not learn from the files it separates.

Withdrawal

Consent can be withdrawn at any time with effect for the future, by no longer selecting the server route. The lawfulness of the processing carried out until then is not affected. Because MixApart works without accounts and deletes automatically, an individual file can only be deleted early by sending a request to the address in section 1.

Nobody has to upload anything in any case. Anyone who decides against it stays with the route on the device. That one simply does not work on some phones, and that is exactly why this section exists.

4. What happens when the site is opened (hosting)

The website runs on servers of Hetzner Online GmbH, Industriestr. 25, 91710 Gunzenhausen, Germany. The servers are located in Germany. A data processing agreement under Art. 28 GDPR is in place with Hetzner.

Server log files

Every time the website is opened, the server automatically stores the following details in log files:

  • IP address
  • date and time of the request
  • page or file requested
  • amount of data transferred and HTTP status code
  • referrer URL
  • browser and operating system used

This includes the requests for the model files that the separation needs. They show that a particular separation mode was loaded, but not what it is applied to.

The processing serves the trouble-free operation of the website as well as the detection and prevention of attacks. The legal basis is Art. 6(1)(f) GDPR, that is, the legitimate interest in secure and stable operation. The log files are deleted automatically after 14 days.

Backups

Hetzner creates automatic backup copies of the server. They contain all the data stored there, including the log files. The backups serve recovery after technical failures, are likewise located in Germany and are overwritten on a rolling basis by newer ones. The legal basis is Art. 6(1)(f) GDPR, that is, the legitimate interest in failure-resistant operation.

5. Content delivery network (CDN)

The website uses the content delivery network of Cloudflare, Inc., 101 Townsend St., San Francisco, CA 94107, USA. Cloudflare sits as a proxy between the browser and the MixApart server, so all requests to the website pass through Cloudflare. This shortens loading times and fends off attacks, for instance denial of service attacks.

In doing so, Cloudflare processes personal data, IP addresses above all, on servers in the USA as well. The legal basis is Art. 6(1)(f) GDPR, that is, the legitimate interest in secure and fast operation of the website.

A data processing agreement under Art. 28 GDPR is in place with Cloudflare. Cloudflare is certified under the EU-U.S. Data Privacy Framework. The transfer to the USA is therefore based on the adequacy decision of the EU Commission (Art. 45 GDPR), and in addition on the Standard Contractual Clauses agreed in the contract (Art. 46(2)(c) GDPR). How long Cloudflare stores logs of its own is set out in Cloudflare's own privacy policy.

The server route from section 3 does not run through Cloudflare. The audio file goes directly to the compute provider.

6. Cookies and what stays in the browser

The website sets no cookies. There is no behavioural analysis, no tracking and no sharing with third parties. A cookie banner is therefore not needed.

MixApart does, however, put two things into the browser cache: the model weights and the runtime files that carry out the separation. Together those are several hundred megabytes that would otherwise have to be downloaded on every visit. Only what comes from the MixApart server is stored. Nothing from the separated file and nothing about the visitor.

On the server route from section 3 one thing is added. The finished stems are delivered with a note that the browser may keep them for one hour, so that a second access does not download everything again. During that hour the stems may therefore sit in the browser cache. They stay on the device while they do, and MixApart cannot see them there.

This storage is technically necessary for the requested function to work at all (§ 25 (2) no. 2 TDDDG, the German implementation of the ePrivacy rules on terminal equipment). It can be cleared at any time through the browser settings under "delete website data".

One thing is added: the language chosen with the EN / DE switch at the top right is remembered by the browser under the key mixapart.lang. It holds two letters and nothing else. The value does not leave the device, and it is cleared the same way as the rest.

7. No forms, no accounts, no third-party content

This website has no contact form, no registration and no comment function. No third-party content such as maps, videos or social media plugins is embedded. All scripts, fonts, images and model files come from our own server. There is no connection to providers such as Google Fonts.

If an email is sent to the address in section 1, the sender address and the content of the message are processed in order to deal with the enquiry and any follow-up questions. The same applies to the telephone number and the subject of the conversation in the case of a call. The legal basis is Art. 6(1)(b) GDPR where the enquiry concerns a contract or its preparation, and otherwise Art. 6(1)(f) GDPR. The message is deleted once it has been dealt with conclusively and no further questions are to be expected, unless statutory retention obligations stand in the way.

8. SSL / TLS encryption

The website uses SSL / TLS encryption. You can recognise an encrypted connection by the browser's address bar starting with "https://" and showing a padlock symbol.
